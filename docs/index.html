🌱 Beginner guide — read this and you are a professional

One idea at a time, each with a real measured number you can check yourself. By the end, you will know more than most interview candidates.

0 · A derivative is a sensitivity. f(x)=exp(sin x) at x₀=1: how much does f move if x moves a little? Exactly f'(1)=cos(1)·e^{sin(1)}≈2.3333. Every gradient in deep learning is this, glued together at scale.
1 · How do we check a derivative? Nudge it. Forward difference (f(x+h)−f(x))/h; central (f(x+h)−f(x−h))/(2h). Nudge too big → truncation error ≈ a·hᵖ. Nudge too tiny → roundoff ≈ b/h. Measured optima: h=1e-8 (forward) and 3.16e-6 (central). E1 fits the textbook slopes +1.01 / +2.00 with r²=1.0000.
2 · A program is a graph. y=(a+b)·c is nodes connected by operations. Each edge has a local derivative (∂out/∂in). The chain rule multiplies local derivatives along every path from y back to a leaf — and adds the contributions of different paths.
3 · The backward pass. Start at the output with grad=1 (how much y changes when y changes — trivially 1) and walk nodes in reversed topological order. Each node pushes grad × local-derivative into its children. That's all backpropagation is.
4 · The bug every tutorial almost makes: = instead of +=. If a leaf is used twice, y=a+a, the correct gradient is 2.0; overwriting (=) gives 1.0. Measured: 64% of random graphs get corrupted — and gradient checking catches 100% of the corrupted ones. E3 is the forensics.
5 · The pass criterion. PyTorch default: |analytic−numeric| ≤ 1e-5 + 1e-3·|numeric|. It is necessary but not sufficient: it can't see bugs where forward and backward are wrong together, or kinks like relu'(0). That's why this repo also uses hand-computed gradients and a PyTorch oracle.
6 · Does it survive randomness? 200/200 random program DAGs pass, up to 40 ops. Error grows only as depth^0.52 (r² 0.98) — a random walk of roundoff, ≈10⁷× below the threshold. E2.
7 · Does it survive reality? Gradients checked on real losses over frozen BTC/ETH/EUR-USD/EUR-JPY data: pass at ≤ 1.8e-7 relative. And the honest part: the little model's test accuracy is statistically indistinguishable from always predicting the majority class (p∈[0.24,0.85]) — reported as a null result. E4. This is a verification demo, not investment advice.
8 · Bit-for-bit reproducibility. The reference engine stores children in a set; iteration order follows memory addresses, so different processes can sum gradients in different orders: measured 4/60 graphs differ by 1 ulp across processes. Storing an ordered tuple: 0/60. E5 — the kind of defect "it worked on my machine" never sees.
9 · Depth. Recursive topological sort hits Python's ~1000 recursion limit; an iterative stack version back-propagates 50,000-node chains (tests/test_topology.py).
10 · Cost. ≈0.9 µs per node at 4096-node chains vs ≈3.8 µs for scalar PyTorch tensors (≈4×), 588 bytes of Python memory per node, ~1.2k–2.2k training steps/s on a 41-parameter MLP. E6.
11 · Reproduce all of it. git clone → pip install -e . → make verify. Claim → script → artifact → test: that loop is the entire thesis of this repository.

🚀 Quick start (3 steps, impossible to fail)

git clone https://github.com/M0-AR/micrograd-verified && cd micrograd-verified
python -m pytest tests/            # 33 passed — no torch required (adds oracle tests if installed)
python experiments/run_all.py      # E1–E6 in ~2 min → results/*.json + RESULTS.md

Or the one-command full check (tests + report): make verify. Container: docker compose run --rm verify.

Site locally: python3 -m http.server 8000 → http://localhost:8000/preview.html (root) or docs/preview.html.
